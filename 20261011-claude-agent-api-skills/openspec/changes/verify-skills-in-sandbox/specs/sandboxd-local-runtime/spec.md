# Spec Delta

## Purpose

GKE Agent Sandbox を使わずに、sandboxd(Agent Sandbox のランタイムデーモン)をローカルの Docker で動かし、エージェントの tool 実行先として使えるようにする。

## ADDED Requirements

### Requirement: sandboxd コンテナの起動
システムは、sandboxd と Python 3 を含むコンテナをローカルの Docker で起動できなければならない(SHALL)。プロセス実行(gRPC)とファイル操作(HTTP)のポートをホストの loopback にだけ公開しなければならない(MUST)。sandboxd は認証を持たないためである。

#### Scenario: ヘルスチェック
- **WHEN** コンテナを起動して、ホストから sandboxd のヘルスエンドポイントを呼ぶ
- **THEN** 正常の応答が返る

#### Scenario: 外部インタフェースに公開しない
- **WHEN** コンテナのポート公開設定を確認する
- **THEN** 公開先は `127.0.0.1` だけである

### Requirement: サンドボックスを識別するマーカー
コンテナには、イメージのビルド時に決めたマーカー値をファイルとして置かなければならない(MUST)。ホスト側には同じファイルが存在しないこと。コマンドがサンドボックス内で実行されたことを、この値で区別できるようにするためである。

#### Scenario: マーカーの読み取り
- **WHEN** sandboxd 経由で `cat` を実行してマーカーファイルを読む
- **THEN** ビルド時に決めた値が返る。ホストで同じパスを読むと存在しない

### Requirement: Python からのプロセス実行とファイル操作
システムは、ホストの Python から sandboxd を呼び、コマンドの実行(終了コード、標準出力、標準エラーを取得)、ファイルの読み取り・書き込み、ディレクトリの一覧を行えなければならない(SHALL)。

#### Scenario: コマンド実行
- **WHEN** `python3 -c 'print(1+1)'` を実行する
- **THEN** 終了コード 0 と標準出力 `2` が得られる

#### Scenario: ファイルの往復
- **WHEN** ファイルを書き込み、同じパスを読み取る
- **THEN** 書き込んだ内容と同じ内容が返る

#### Scenario: 失敗の伝達
- **WHEN** 存在しないファイルを読む、または終了コードが 0 以外になるコマンドを実行する
- **THEN** 呼び出し側は失敗の内容(エラーや終了コード)を受け取る。例外で落ちて検証全体が止まることはない
