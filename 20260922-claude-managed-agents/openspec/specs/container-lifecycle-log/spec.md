# container-lifecycle-log Specification

## Purpose

セッション毎コンテナの起動・終了イベントを構造化ログとして残し、将来ここにワークスペース永続化処理を挟み込めることを、まずイベントが確実に取れるという形で確認する。

## Requirements

### Requirement: ライフサイクルイベントの記録

システムは、セッション毎コンテナの起動時と終了時に 1 行ずつ、追記専用のログファイルへ構造化イベント（JSON Lines）を記録しなければならない（SHALL）。

#### Scenario: 起動イベントが記録される

- **WHEN** work item を受け取ってコンテナを起動する
- **THEN** `event` が起動を示す値のレコードが 1 行追記され、タイムスタンプ（UTC, ISO 8601）・session ID・work ID・environment ID・コンテナ名を含む

#### Scenario: 終了イベントが記録される

- **WHEN** コンテナが終了する
- **THEN** `event` が終了を示す値のレコードが 1 行追記され、対応する起動イベントと同じ session ID / work ID / コンテナ名、終了コード、および起動からの経過時間（ミリ秒）を含む

#### Scenario: 起動と終了が対応付けられる

- **WHEN** 複数のコンテナが並行または連続して起動・終了する
- **THEN** 各終了イベントは work ID とコンテナ名で一意に起動イベントと対応付けられる

#### Scenario: 1 行 1 イベントで機械可読である

- **WHEN** ログファイルを 1 行ずつ JSON としてパースする
- **THEN** すべての行がパースに成功し、途中で切れた行や複数行にまたがるレコードが存在しない

### Requirement: 異常終了時の記録

システムは、コンテナが非ゼロ終了コードで終わった場合、起動に失敗した場合、およびオーケストレータがシグナルで停止した場合にも、終了イベントを記録しなければならない（SHALL）。

#### Scenario: コンテナが異常終了する

- **WHEN** コンテナのエントリポイントが非ゼロ終了コードで終わる
- **THEN** 終了イベントが記録され、その終了コードと、エラーであることを示すフィールドを含む

#### Scenario: コンテナの起動自体に失敗する

- **WHEN** イメージが存在しない等の理由でコンテナの起動に失敗する
- **THEN** 起動失敗を示すイベントが記録され、オーケストレータはその work item で停止せず次のポーリングを続ける

#### Scenario: オーケストレータが停止しても対応が崩れない

- **WHEN** 処理中にオーケストレータへ SIGTERM を送る
- **THEN** 起動中のコンテナに対する終了イベントが記録されてからオーケストレータが終了し、終了イベントのない起動イベントが残らない

### Requirement: 永続化フックの接続点

ライフサイクルイベントの記録処理は、将来ワークスペースの保存・復元処理を挿入できる単一の接続点として実装されなければならない（SHALL）。この変更では永続化そのものは実装しない。

#### Scenario: 起動前・終了後にフックを挟める位置が明示されている

- **WHEN** オーケストレータの実装を読む
- **THEN** コンテナ起動の直前と終了の直後にそれぞれ処理を挿入できる箇所が 1 か所ずつ存在し、そこにワークスペースの復元・保存を後から追加できることがコメントで示されている

#### Scenario: ログ出力先が設定可能である

- **WHEN** ログファイルのパスを設定で指定する
- **THEN** 指定した場所にイベントが追記され、既定値でもプロジェクト内の既知のパスに記録される
