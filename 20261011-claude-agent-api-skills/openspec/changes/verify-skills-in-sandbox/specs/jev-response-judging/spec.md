# Spec Delta

## Purpose

Jev(TypeSafe System One)を判定器として使い、エージェントの自然文の応答が期待する事実を述べているかを、テストの合否として判定できるようにする。

## ADDED Requirements

### Requirement: Jev による応答判定
システムは、エージェントの応答テキストと真偽の質問を Jev に送り、確率(0〜1)を得て、閾値で合否を判定できなければならない(SHALL)。判定は、合言葉やマーカーなどの値を述べているか、スクリプトの実行が失敗したと述べているか、の判定に使う。

#### Scenario: 値を述べた応答
- **WHEN** 合言葉を含む応答を「この文章は値 X を述べているか」という質問で判定する
- **THEN** 確率が閾値を超え、合格になる

#### Scenario: 値を述べていない応答
- **WHEN** 合言葉を含まない応答を同じ質問で判定する
- **THEN** 確率が閾値以下になり、不合格になる

### Requirement: 文字列照合との併用
システムは、値が決まっている判定では、Jev の判定に加えて文字列の照合も行い、両方の結果を記録しなければならない(MUST)。結果が食い違った場合は、報告書に記載する。

#### Scenario: 判定の食い違い
- **WHEN** 文字列照合と Jev の判定が一致しない
- **THEN** その応答と両方の判定結果が報告書に記載される

### Requirement: 認証情報の扱い
システムは、`.env` の `JEV_API_TOKEN` と `CLAUDE_API_KEY` を環境変数としてだけ読み込まなければならない(MUST)。これらの値をログ、結果ファイル、報告書、コミットに含めてはならない。

#### Scenario: トークンを出力しない
- **WHEN** 検証を実行して結果ファイルと報告書を生成する
- **THEN** どちらのトークンの文字列も、生成物に含まれていない
