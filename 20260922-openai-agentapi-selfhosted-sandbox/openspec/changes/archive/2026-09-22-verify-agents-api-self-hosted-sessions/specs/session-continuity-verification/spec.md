# Spec Delta

## Purpose

セッション終了後の追加入力が既存の対話を継続することと、将来のワークスペース復元に必要な識別情報を取得できることを検証する。

## ADDED Requirements

### Requirement: 同じセッションで対話を継続する
検証ハーネスは作成したセッション ID を保存し、その ID に追加入力を送って以前の会話に基づく応答を確認できなければならない (SHALL)。別のセッションでは同じ会話文脈が共有されてはならない (MUST NOT)。

#### Scenario: コンテナを替えて対話を継続する
- **WHEN** 最初のターンで会話内だけに検証用合言葉を伝え、コンテナを停止した後に同じセッションへ合言葉を尋ねる
- **THEN** 新しいコンテナで実行された追加入力への応答は合言葉を使い、セッション ID は変わらない

#### Scenario: 別セッションでは文脈がない
- **WHEN** 同じ質問を新しく作成した別セッションに送る
- **THEN** 先のセッションの合言葉を知っているものとして回答しない

### Requirement: ワークスペース復元キーの材料を示す
検証結果は、コンテナ起動前に利用できるセッション ID と環境 ID、コンテナの停止時に利用できる同じ識別子、ワークスペースを保存・復元する処理を挿入できる時点を示さなければならない (SHALL)。会話状態の継続とコンテナ内ファイルの継続を別々に判定しなければならない (SHALL)。

#### Scenario: ファイル状態の境界を確認する
- **WHEN** 最初のコンテナが作成した一意のファイルを、永続ストレージを使わずに停止後の新しいコンテナで探す
- **THEN** 検証結果は会話が継続してもファイルが引き継がれないことを明示し、実測結果が異なればその理由と構成を記録する

### Requirement: 再現可能な検証結果を残す
検証手順は必要な資格情報、起動方法、各シナリオの合否基準、観測した ID とライフサイクルログの確認方法を示さなければならない (SHALL)。実測していない事項を成功として報告してはならない (MUST NOT)。

#### Scenario: 検証を実施せずに結果を確認する
- **WHEN** 必要な API 権限や実行環境がなく実 API の通し試験を実施できない
- **THEN** 結果には未実施と理由が記録され、設計上の見込みと実測結果が区別される
