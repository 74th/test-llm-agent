# Spec Delta

## Purpose

コンテナ内にしか存在しない GCP サービスアカウントキーを使ってエージェントが BigQuery のテーブルへ実際にアクセスできることを示し、作業がコンテナ内の情報で行われていることを確定させる。

## ADDED Requirements

### Requirement: サービスアカウントキーのマウント

システムは、GCP サービスアカウントキーをホスト側からコンテナへ読み取り専用でマウントし、コンテナ内のアプリケーション既定資格情報として解決可能にしなければならない（SHALL）。self-hosted 環境では vault の `environment_variable` credential が使えないため、キーはマウントで供給する。

#### Scenario: キーがコンテナ内から読める

- **WHEN** セッションでエージェントにマウント先のパスを確認させる
- **THEN** キーファイルが存在し、`GOOGLE_APPLICATION_CREDENTIALS` がそのパスを指している

#### Scenario: キーは読み取り専用である

- **WHEN** エージェントがキーファイルへの書き込みを試みる
- **THEN** 書き込みは失敗する

#### Scenario: キーはホスト側にのみ原本がある

- **WHEN** コンテナイメージの内容を検査する
- **THEN** キーファイルはイメージに焼き込まれておらず、マウントによってのみ提供されている

### Requirement: エージェントによる BigQuery アクセス

システムは、エージェントがその場でスクリプトを書いて実行し、既存テーブル `nnyn-dev.house_monitor.co2` に対してクエリを実行できる状態を提供しなければならない（SHALL）。

#### Scenario: エージェントが自力でクエリを実行する

- **WHEN** エージェントに「`nnyn-dev.house_monitor.co2` の行数と直近のデータを調べてほしい」と依頼する
- **THEN** エージェントはコンテナ内でスクリプトを作成・実行し、クエリ結果に基づいた回答を返す

#### Scenario: 事前に用意したクエリスクリプトに依存しない

- **WHEN** リポジトリに BigQuery 用の完成済みスクリプトを置かない状態で依頼する
- **THEN** エージェントは必要なコードをその場で書いて実行し、タスクを完了できる

#### Scenario: クエリ結果がコンテナ由来であることが確認できる

- **WHEN** セッションのイベントストリームを確認する
- **THEN** `bash` 等のツール実行がすべて自前コンテナ側のワーカー経由で行われており、クエリ結果はそのツール出力として得られている

### Requirement: 最小権限のサービスアカウントを作る Terraform

システムは、`nnyn-dev` プロジェクトにおいて、当該テーブルの読み取りとクエリ実行に必要な権限のみを持つサービスアカウントを作成する Terraform 構成を提供しなければならない（SHALL）。

#### Scenario: サービスアカウントと権限が作られる

- **WHEN** Terraform 構成を適用する
- **THEN** サービスアカウントが作成され、プロジェクトに対するジョブ実行権限と、対象テーブル（またはそのデータセット）に対する読み取り権限が付与される

#### Scenario: 権限が対象テーブルに限定されている

- **WHEN** 付与された権限を確認する
- **THEN** プロジェクト全体に対する BigQuery データ読み取り権限は付与されておらず、読み取りは対象テーブルもしくは `house_monitor` データセットのスコープに限定されている

#### Scenario: 既存リソースを作り直さない

- **WHEN** Terraform 構成を適用する
- **THEN** 既存の `house_monitor.co2` テーブルおよびデータセットは Terraform の管理対象として新規作成されず、参照のみで扱われる

#### Scenario: 対象が設定値として与えられる

- **WHEN** Terraform 構成を読む
- **THEN** プロジェクト ID・データセット・テーブル・サービスアカウント名が変数として定義され、既定値が検証対象を指している（サービスアカウント名の既定値は `test-claude-managed-agents`）

#### Scenario: キーの取得方法が定まっている

- **WHEN** Terraform の出力を確認する
- **THEN** サービスアカウントのメールアドレスが出力され、キーの発行方法（Terraform で発行するか `gcloud` で人間が発行するか）が構成内で明示されている
