# Spec Delta

## Purpose

Jev(構造化意思決定モデル)を判定器として使い、LLM の応答を pytest のユニットテストとして合否判定できるかを検証可能にする。

## ADDED Requirements

### Requirement: Jev による応答判定
システムは、エージェントの応答テキストを Jev に与え、型付きの質問(真偽確率など)への回答を得て、閾値でテストの合否を判定できなければならない(SHALL)。

#### Scenario: 期待内容を含む応答の合格
- **WHEN** 期待する固有値に言及した応答を「この応答は値 X に言及しているか」という質問つきで Jev に送る
- **THEN** 該当確率が閾値以上で、テストが合格する

#### Scenario: 含まない応答の不合格
- **WHEN** 固有値に言及しない応答を同じ質問で Jev に送る
- **THEN** 該当確率が閾値未満となり、判定が不合格になる

### Requirement: 認証情報の扱い
システムは、`.env` の `JEV_API_TOKEN` を環境変数経由でのみ読み込まなければならない(MUST)。トークンをログ・報告書・コミットに含めてはならない。

#### Scenario: トークンの非出力
- **WHEN** テストを実行してログと報告書を生成する
- **THEN** トークン文字列はどこにも出力されない

### Requirement: 判定の信頼性の記録
システムは、Jev の判定が決定的な文字列一致とどの程度一致するか、および使用トークン数を報告書に記録しなければならない(MUST)。

#### Scenario: 判定結果の比較
- **WHEN** 同じ応答群を文字列一致と Jev の両方で判定する
- **THEN** 両者の一致状況と `usage` のトークン数合計が報告書に記載される
