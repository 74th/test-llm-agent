# Spec Delta

## Purpose

セッションが Anthropic 側ではなくこちらのコンテナ内で実行されていることを、そのコンテナにしか存在しない資格情報でしか到達できないリソースへアクセスさせて証明するための、資格情報の供給範囲と証明手順を定める。

## ADDED Requirements

### Requirement: 検証用サービスアカウントが最小権限で定義される

GCP プロジェクト `nnyn-dev` に、検証専用のサービスアカウントが Terraform で定義されなければならない（SHALL）。権限は BigQuery のクエリ実行と、テーブル `nnyn-dev.house_monitor.co2` の読み取りに限られる（SHALL）。データセットやプロジェクト全体に対する広い読み取り権限を与えてはならない（MUST NOT）。

Terraform は既存の BigQuery テーブルを作成も変更もしてはならない（MUST NOT）。付与するのは IAM バインディングのみである（SHALL）。

#### Scenario: 対象テーブルを読める

- **WHEN** このサービスアカウントで `nnyn-dev.house_monitor.co2` に対するクエリを実行する
- **THEN** クエリが成功し、結果が返る

#### Scenario: 対象外のテーブルは読めない

- **WHEN** このサービスアカウントで同じデータセット内の別テーブル、または別データセットのテーブルに対するクエリを実行する
- **THEN** 権限エラーで拒否される

#### Scenario: 既存テーブルが変更されない

- **WHEN** `terraform plan` を実行する
- **THEN** BigQuery テーブルそのものの作成・変更・削除は計画に含まれない

### Requirement: サービスアカウントキーがコンテナ内にのみ存在する

サービスアカウントキーは、コンテナへ読み取り専用でマウントされることでのみ供給されなければならない（SHALL）。キーはイメージレイヤ、リポジトリの追跡対象ファイル、マウントするワークスペースのいずれにも含まれてはならない（MUST NOT）。セッションは環境変数からキーの場所を知る（SHALL）。

#### Scenario: セッションからキーが見える

- **WHEN** セッション内の Claude が資格情報のパスを示す環境変数を読む
- **THEN** 読み取り可能なキーファイルがその場所に存在する

#### Scenario: キーがリポジトリに入らない

- **WHEN** リポジトリの追跡対象ファイルとビルド済みイメージを走査する
- **THEN** サービスアカウントキーの内容が見つからない

#### Scenario: キーがワークスペースの seed 経路に乗らない

- **WHEN** セッションへ seed される config ディレクトリの中身を確認する
- **THEN** サービスアカウントキーが含まれていない

### Requirement: 両モードで同じ資格情報が供給される

常駐モードとセッション毎モードのどちらでも、セッションは同じサービスアカウントキーに同じパスで到達できなければならない（SHALL）。セッション毎モードでは、この供給はプロビジョナが行い、プロビジョナ固有の記法へ変換される（SHALL）。

#### Scenario: モードによらず到達できる

- **WHEN** それぞれのモードで起動したセッションから資格情報のパスを確認する
- **THEN** どちらも同じパスにキーが存在する

### Requirement: セッションが自作スクリプトで実行場所を証明する

検証は、あらかじめ用意したスクリプトを実行させるのではなく、セッション内の Claude にその場で BigQuery へアクセスするスクリプトを書かせ、実行させることで行われなければならない（SHALL）。これによりコンテナ内のツールチェーンと資格情報の両方が使えていることを同時に確認する。

イメージには、セッションが BigQuery へアクセスする手段が含まれていなければならない（SHALL）。

#### Scenario: その場で書いたスクリプトが成功する

- **WHEN** セッション内の Claude に `nnyn-dev.house_monitor.co2` の行数を数えるスクリプトを書いて実行するよう指示する
- **THEN** Claude はスクリプトを作成して実行し、行数を回答する

#### Scenario: 実行場所の証明になる

- **WHEN** 上記が成功する
- **THEN** そのキーはこのコンテナにしか存在しないため、セッションがこのコンテナ内で実行されたと結論できる

#### Scenario: 失敗が切り分けられる

- **WHEN** スクリプトの実行が失敗する
- **THEN** 資格情報が届いていないのか、権限が不足しているのか、ネットワークが遮断されているのかを、エラー内容から区別できる
