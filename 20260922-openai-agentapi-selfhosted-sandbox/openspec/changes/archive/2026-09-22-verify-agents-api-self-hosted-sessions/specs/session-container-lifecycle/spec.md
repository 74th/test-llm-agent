# Spec Delta

## Purpose

各 Agents API セッションに専用コンテナを割り当て、起動から停止、同じセッションへの再接続までの対応関係を観測できるようにする。

## ADDED Requirements

### Requirement: セッション単位でコンテナを分離する
検証ハーネスは一つのセッションに対して同時に一つ以下の稼働中コンテナを割り当て、異なるセッションには異なるコンテナを割り当てなければならない (SHALL)。同じセッションへの重複した接続要求でコンテナを重複起動してはならない (MUST NOT)。

#### Scenario: 二つのセッションを並行実行する
- **WHEN** 二つの self-hosted セッションへ並行して入力を送る
- **THEN** それぞれのセッション ID に異なる環境 ID とコンテナ ID が対応し、各セッションでコンテナ固有マーカーを読み取れる

#### Scenario: 接続要求が重複する
- **WHEN** 同じセッションに対して接続要求が重複して届く
- **THEN** 稼働中コンテナは一つのままで、両要求は同じ割り当てを参照する

### Requirement: 安全に停止して再起動できる
検証ハーネスはターンの成功または失敗を確認し、追加入力との競合を解決してからコンテナを停止しなければならない (SHALL)。同じセッションが後で実行環境を再要求した場合、元のセッションの環境 ID を用いて新しいコンテナを接続できなければならない (SHALL)。

#### Scenario: ターン終了後に停止する
- **WHEN** ターンが完了し、セッションに新たな実行要求がない
- **THEN** 対応コンテナが停止し、その終了が記録される

#### Scenario: 停止中に追加入力が到着する
- **WHEN** コンテナ停止処理中に同じセッションへの追加入力が届く
- **THEN** 追加入力は稼働中コンテナか新しいコンテナのどちらかで処理され、重複コンテナや未処理の入力を残さない

### Requirement: ライフサイクル対応を記録する
検証ハーネスはコンテナの起動、接続、切断、停止、起動失敗について、時刻、セッション ID、環境 ID、コンテナ ID、結果を対応付けて記録しなければならない (SHALL)。

#### Scenario: 停止後に同じセッションを再開する
- **WHEN** 停止済みのセッションへ追加入力を送って新しいコンテナを起動する
- **THEN** ログには同じセッション ID と環境 ID に対応する二つの異なるコンテナ ID、および各コンテナの起動と停止が残る
