# self-hosted-environment Specification

## Purpose

Managed Agents のツール実行を Anthropic のクラウドサンドボックスではなく自前のコンテナで行わせ、常駐単一コンテナとセッション毎コンテナの 2 つの起動方式がどちらも成立することを検証可能にする。

## Requirements

### Requirement: 自前コンテナでのツール実行

システムは、Managed Agents のセッションが使う `bash` / `read` / `write` / `edit` / `glob` / `grep` の実行を、利用者が管理するコンテナ内で行える環境を提供しなければならない（SHALL）。エージェントループそのものは Anthropic 側で動作し、コンテナへの接続は outbound のみである。

#### Scenario: コンテナ内のファイルシステムが見える

- **WHEN** セッションでエージェントに、コンテナ内の作業ディレクトリ（`/workspace`）にあるファイルの一覧と内容を尋ねる
- **THEN** エージェントはコンテナのイメージ・マウントに実際に存在するファイルを返し、Anthropic のクラウドサンドボックスの内容ではないことが確認できる

#### Scenario: コンテナ固有のマーカーで実行場所が特定できる

- **WHEN** コンテナイメージに検証用のマーカーファイル（ホスト名・イメージ識別子などを含む）を置き、エージェントにそれを読ませる
- **THEN** マーカーの内容がそのまま返り、ツールが当該コンテナ内で実行されたことが一意に確定する

#### Scenario: 環境がクラウドではなく self-hosted である

- **WHEN** 検証に使う Environment の設定を照会する
- **THEN** `config.type` が `self_hosted` であり、pool / capacity / networking といったクラウド専用の設定を持たない

### Requirement: モード A - 常駐単一コンテナ

システムは、1 つの常駐コンテナがワークキューをポーリングし続け、複数のセッションを同一コンテナで順次処理する起動方式を提供しなければならない（SHALL）。

#### Scenario: 常駐ワーカーが複数セッションを処理する

- **WHEN** モード A のワーカーコンテナを起動し、同じ Environment を参照するセッションを 2 つ続けて実行する
- **THEN** どちらのセッションもツール実行に成功し、ワーカーコンテナは両セッションを通じて起動したままである

#### Scenario: 常駐ワーカーは状態を持ち越す

- **WHEN** 1 つ目のセッションで作業ディレクトリにファイルを作らせ、2 つ目のセッションでそのファイルを読ませる
- **THEN** 同一コンテナを共有しているため 2 つ目のセッションからそのファイルが読める（モード A の性質として記録される）

#### Scenario: 停止シグナルで正常終了する

- **WHEN** 常駐ワーカーに SIGTERM を送る
- **THEN** 処理中の work item を終えてから終了し、強制 kill を必要としない

### Requirement: モード B - セッション毎コンテナ

システムは、ワークキューから受け取った work item ごとに使い捨てコンテナを起動し、その中で 1 件だけ処理して終了させる起動方式を提供しなければならない（SHALL）。ポーリングを行うオーケストレータはホスト側に常駐し、コンテナの起動はオーケストレータが行う。

#### Scenario: work item ごとにコンテナが起動・終了する

- **WHEN** モード B のオーケストレータを起動し、1 セッション内で 2 回続けてエージェントに作業を依頼する（2 ターン）
- **THEN** 依頼ごとにコンテナが起動して終了し、ライフサイクルログにその回数分の開始・終了イベントが記録される

#### Scenario: 使い捨てコンテナは状態を持ち越さない

- **WHEN** 1 ターン目で作業ディレクトリにファイルを作らせ、2 ターン目でそのファイルを読ませる
- **THEN** コンテナが作り直されているためファイルは存在せず、ワークスペース永続化が必要であることが検証結果として確定する

#### Scenario: セッション以外の work item を取り違えない

- **WHEN** オーケストレータがセッション種別でない work item を受け取る
- **THEN** コンテナを起動せずにその item を処理済みとして扱い、エラーで停止しない

### Requirement: ワーカーへの資格情報の受け渡し

システムは、ワーカーが Anthropic のワークキューに接続するための environment key と、work item ごとの secret を、ログに残さず必要なコンテナにのみ渡さなければならない（SHALL）。

#### Scenario: 使い捨てコンテナに必要な環境変数が渡る

- **WHEN** モード B でコンテナを起動する
- **THEN** そのセッションに対応する session ID / work ID / environment ID / environment key / work secret が環境変数として渡され、他のセッション用のコンテナには渡らない

#### Scenario: 秘密情報がログに出ない

- **WHEN** ライフサイクルログおよびワーカーの標準出力を検査する
- **THEN** environment key と work secret の値がどこにも出力されていない

#### Scenario: 組織スコープの API キーはワーカーホストに置かない

- **WHEN** ワーカーコンテナおよびオーケストレータの環境変数を検査する
- **THEN** `ANTHROPIC_API_KEY`（組織スコープ）は設定されておらず、ワーカーは environment key のみで認証している
